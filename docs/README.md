# Документация Switch Generator

## Как плагин подключается к VS Code

VS Code читает `package.json` (манифест) ещё до запуска плагина. Из него он узнаёт:

- `main` — файл с кодом (`./extension.js`);
- `contributes.commands` — команду `switchGen.generate` с названием «Создать switch-case», она появляется в палитре команд;
- `contributes.keybindings` — сочетание клавиш `Ctrl+Alt+E` / `Cmd+Alt+E`, работает, когда фокус в редакторе;
- `activationEvents` — пустой список: начиная с VS Code 1.74 плагин включается сам, когда вызывают его команду.

Когда команду вызывают первый раз, VS Code загружает `extension.js` в отдельном процессе Extension Host и вызывает функцию `activate`.

## Порядок работы

1. `activate` регистрирует команду.
2. Пользователь вызывает команду, запускается `generateSwitch`.
3. Появляется окошко ввода (`vscode.window.showInputBox`). Если нажать Esc — работа заканчивается.
4. `parseCases` превращает введённый текст в список меток `case`.
5. Если список пустой — выводится сообщение об ошибке.
6. `getExpression` выбирает, что писать в скобках `switch`.
7. `buildSwitch` собирает текст с отступами текущей строки.
8. Текст вставляется через `editor.edit`, поэтому вставку можно отменить через Ctrl+Z.

## Функции

### `activate(context)`
Регистрирует команду `switchGen.generate` и кладёт её в `context.subscriptions`, чтобы VS Code сам удалил её при выключении плагина.

### `deactivate()`
Вызывается при выключении плагина. Пустая, потому что убирать нечего.

### `generateSwitch()`
Главная функция. Берёт активный редактор, спрашивает значения, вызывает остальные функции и вставляет готовый код. На пустой строке код заменяет строку, иначе вставляется на новую строку под курсором.

### `getExpression(editor)`
Возвращает выделенный текст, если он есть. Иначе слово под курсором (`getWordRangeAtPosition`). Если курсор не на слове — `"x"`.

### `parseCases(input)`
Режет ввод по запятым и пробелам (`/[,\s]+/`), для каждого куска вызывает `toLabels`. Множество `Set` запоминает уже добавленные метки, поэтому повторы не попадают в результат. Порядок меток сохраняется в массиве.

### `toLabels(part)`
- `1-5` (регулярное выражение `/^(-?\d+)-(\d+)$/`) → `1, 2, 3, 4, 5`, не больше 101 числа, чтобы плагин не завис на `1-99999999`;
- одна латинская буква → символ в кавычках: `a` → `'a'`;
- всё остальное остаётся как есть (`10`, `RED`).

### `buildSwitch(expression, labels, indent, tab)`
Собирает строки в массив и склеивает через `\n`:

```
<indent>switch (<expression>) {
<indent><tab>case <метка>:
<indent><tab><tab>break;
...
<indent><tab>default:
<indent><tab><tab>break;
<indent>}
```

## Структуры данных

| Структура | Где | Зачем |
|---|---|---|
| массив `result` | `parseCases` | список меток `case` в порядке ввода |
| множество `Set` `seen` | `parseCases` | быстро проверять, была ли метка, и убирать повторы |
| массив `numbers` | `toLabels` | числа из раскрытого диапазона |
| массив `lines` | `buildSwitch` | строки будущего кода |

## Ограничения

- не понимает диапазоны букв (`a-e`);
- каждый `case` заканчивается на `break`.
